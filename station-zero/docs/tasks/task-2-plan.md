## 3. Verifying visuals without a human
Facts: `xvfb-run` and `Xvfb` exist (/usr/bin); Mesa is present, no Vulkan ICD. The main session has VERIFIED real rendering with this command (1280x720 PNG correct, ALSA warnings harmless):
`xvfb-run -a -s "-screen 0 1280x720x24" godot --rendering-driver opengl3 --path station-zero --script <script>`
A SceneTree script that awaits two process frames and then `RenderingServer.frame_post_draw`, then calls `root.get_texture().get_image().save_png(path)`, works. This planning session did not run it itself.
- The `--headless` flag uses the dummy renderer: no pixels, so screenshot runs must not use it. The approach is:
  1. Primary (verified): `tools/shot.gd` is a SceneTree script run with the command above plus user args (`-- --seed 42 --hours 120 --zoom 3 --out path.png`). It builds the world view, steps the sim to the chosen moment, awaits two process frames and `frame_post_draw`, and saves the PNG. A `tools/shots.sh` wrapper renders the whole shot list (section 5) in one go. Step 3 is therefore a short harness commit, not a feasibility spike.
  2. Fallback A (only if a later environment change breaks 1): `--write-movie out.avi --quit-after N` under xvfb, then extract frames in Python.
  3. Fallback B (no GL at all): render the view in a CPU path, `tools/preview.py` composes the same layers with Pillow from the manifest and a JSON dump of sim state (`tests/dump_state.gd`). It tests layout, door rects and construction crops, not the engine draw code. Say so in the report.
  4. Always on, even if 1 works: pixel assertions in GDScript tests on view-model output, and Python sampling of the shot (for example, at night the window pixels brighter than at day; offline building darker than online).
- Shots go to `station-zero/docs/shots/task-2/` (small PNGs, 1280x720 plus 2x crops) with a manifest of (seed, hours, zoom, camera). The main session opens them; the plan expects at least 12 images (steps 11-16).

## 4. Ambiguities and recommended resolutions
- A1 Sheet grid. Sheets are 1024x1024 with 4x4 cells of about 256 and thin dark separator lines, so cell edges are not exactly at multiples of 256. Resolve: find the separator lines from the column and row profile of "dark and not magenta" pixels, snap to the nearest 256 multiple if none is found, inset 6 px from each line, key magenta, crop to content per cell, then one shared scale per sheet from the tallest frame and a common feet baseline, pivot = bottom center of the shared box (not per-frame bbox, which would make the walk jitter). Test: all 16 cells nonempty, same size, feet baseline equal.
- A2 Which pixels recolor. Jumpsuit pixels with HSV saturation < 0.18, value 0.35..0.95, and not outline (value < 0.3). Skin, hair, boots (dark) and the gold are excluded by these bounds. Recolor keeps shading: output = role color x (pixel luma / mean suit luma), clamped. Pre-bake 4 role atlases rather than a shader (simpler, testable by pixel). The crate in the carry frame is gray and will tint; accepted for now. Thresholds in data/art.json; the test counts changed pixels vs gray pixels (>= 95% of gray suit pixels changed, 0 skin pixels changed using the idle-front face region).
- A3 Door rects. Habitat (0.4362, 0.6895, 0.5627, 0.8714) and reactor (0.4211, 0.7496, 0.5802, 0.8706) are normalized to the keyed, cropped image, and the crop box changes if keying changes. Resolve: the pipeline crops exactly as the prototype did (bbox of alpha > 0 after keying and erosion) and a test asserts the rect stays inside opaque pixels and the rect's center pixel is "door-like" (not magenta). Workshop and greenroom rects are not given; estimates from the 1024 raws (workshop about 0.34, 0.57, 0.66, 0.69; green room about 0.42, 0.57, 0.58, 0.71, after normalizing to crop) are provisional, measured by the pipeline and confirmed on the review overlay. Mode `rollup` for workshop (panel slides up and clips), `split` for the rest.
- A4 Art vs sim size. The sim picks rect sizes of 10..14 x 8..10 tiles; art has one aspect. Resolve as the prototype: stretch art to (w+6, h+6) world px; check at most about 25% aspect distortion over the sim's size range and record it; do not change sim sizes. Needs a look in shots (Herby).
- A5 Performance with 160 beings. Most are inside (no x,y), so only EVA/transit beings plus the beings of one open building draw. Resolve: draw outside beings from one pooled set of Sprite2D with atlas regions (or one `_draw` per layer), cull by camera rect, footprints (cap 2,200) in a single MultiMesh or batched `draw_texture`, light layers as a few full-screen quads, view refresh by sim step delta not every frame, redraw only when the camera or sim step changes. Interior beings only for the roof-open building (at most about 25). Budget: view-model update for 160 beings under 2 ms and under 300 nodes total, measured in step 17; frame time under xvfb is reported but informational (llvmpipe is slow).
- A6 Sim/view separation. Animation state (walk phase, facing, door openness, interior slots, particles, selection pulse, camera) lives only in view/model, keyed by being or building id; it is derived from sim data read each refresh and never written back. View code uses a view-owned `RandomNumberGenerator` seeded from the being id, never `SimRng` or `randf()` global. No sim file is edited in Task 2; if the view needs a derived value (for example, a being inside has no position), the view computes it. At 100x and 1000x the sim steps many hours per frame: animation runs on real time, with walk phase clamped and positions interpolated from the last two sim samples.
- A7 Facing. Outside beings have `heading` (radians). Resolve: front if heading points down, back if up (vertical dominance 1.25x, as proto L1452), else side with mirror for left; idle uses front; work/mining use side with the heading's sign. In tunnels, direction comes from corridor p1 to p2 with `from_a`.
- A8 Helmet lamp. Front and side sheet frames already contain a lamp; the glow is drawn additively at an anchor stored per row in `sheets/*.json` (back view: top center). Intensity from `lamp_on` (night rule from the sim, not recomputed). Jumpsuit has no lamp (they are never outside).
- A9 Interiors. The interior art is an overlay stretched to the building rect (door gap at the bottom matches the building's front door). Beings inside get slots (bunks, table, sofa, kitchen) in normalized coordinates measured from the art and stored in art.json; sleepers go to bunks, others wander between slots with pauses; these positions are cosmetic only.
- A10 Gray-background interiors. Habitat/comms interiors are 1264x848 on a gray background, not magenta: key by flood fill from the corners with a color-distance tolerance, then verify the outer wall stays opaque. Test: corners transparent, 3 points on the wall opaque.
